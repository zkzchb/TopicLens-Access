Common access flow

不同入口，共用同一条接入逻辑

正式接口尚未冻结，因此下面展示的是 Access Layer 的目标流程，而不是已经发布的生产接口。实际服务地址、认证方法和字段名称会在公开契约稳定后替换这里的占位符。

01

选择入口

官方 Web、WorkBuddy Skill、MCP、自托管客户端或 API。

02

连接公开服务

客户端只连接版本化的 Public Service Interface，不直接访问 Core 内部模块。

03

提交研究请求

提供 Topic、问题、必要约束和希望获得的研究输出。

04

获取状态与结果

通过客户端或工具查看任务状态，并取得研究结果与公开证据信息。

05

继续工作流

人可以阅读结果，Agent 也可以把结果继续用于写作、分析或其他任务。

WorkBuddy & Agent

让 TopicLens 成为 Agent 的专业研究工具

对于 WorkBuddy、Codex、Claude Code、OpenClaw 这类 Agent，TopicLens 不需要成为新的聊天入口。更自然的方式是通过 Skill、MCP 或 Tool Calling，把它作为 Agent 可调用的一项研究能力。

WORKBUDDY SKILL · COMING SOON

在 WorkBuddy 中调用 TopicLens

规划中的 `topiclens-research` Skill 将负责把用户的专业研究需求转换成 TopicLens 的公开请求，并把研究状态和结果带回 WorkBuddy 工作流。

  • 用户继续在 WorkBuddy 中描述研究问题；
  • Skill 负责调用公开 TopicLens 服务；
  • 研究结果可继续进入资料整理、写作或其他 Workflow；
  • Skill 只依赖公开契约，不接触 Router / Graph / Field 的私有实现。

计划中的安装 / 配置方式

  1. 安装 Skill：从公开仓库或正式发布地址安装 `topiclens-research`。
  2. 配置服务：填写 TopicLens Public Service Interface 地址。
  3. 配置认证：如公开服务需要认证，按正式文档配置访问凭据。
  4. 发起任务：在 WorkBuddy 中让 Skill 执行研究，并继续处理返回结果。
WorkBuddy Skill 配置示意PLACEHOLDER
skill: topiclens-research
service: <TOPICLENS_PUBLIC_SERVICE_URL>
auth: <AUTH_CONFIGURATION>
status: coming-soon

以上只是页面占位符，不代表已经冻结的 Skill Manifest、字段名称或认证格式。

Web clients

浏览器入口：官方 Web 与自托管 Web

如果希望使用 TopicLens，而不是把它集成进其他软件，Web 会是最直接的入口。官方 Web 和自托管 Web 的差别主要在访问界面由谁部署；两者背后的研究能力仍来自同一个 TopicLens 服务。

OFFICIAL WEB · COMING SOON

打开浏览器，直接开始研究

官方 Web 将承担最终用户的主要入口：输入研究问题、查看状态与结果，并逐步管理 Topic 与历史研究。无需了解 Skill、MCP 或 API。

计划中的使用流程

  1. 打开 TopicLens 官方 Web 地址；
  2. 按公开服务要求完成必要的访问或认证；
  3. 输入研究问题、Topic 与约束；
  4. 查看研究状态、结果及可公开的证据信息。
Official WebCOMING SOON
https://<TOPICLENS_OFFICIAL_WEB>/
SELF-HOSTED WEB · PLANNED

部署自己的入口，而不是自己的 Core

自托管 Web 可集成到自己的网站、域名、样式和入口环境，但客户端仍通过公开接口访问 TopicLens Core。

  • 可独立部署和升级访问端；
  • 不会获得或部署 TopicLens Core 后端源码；
  • 不会直接获得 Field 私有知识资产；
  • 只依赖稳定的公开服务契约。

API & SDK

把 TopicLens 集成进你的应用

当 Web、Skill 或 MCP 不能覆盖你的集成场景时，后续公开的 API / SDK 将提供更底层、稳定的程序化访问方式。公开的是服务契约，而不是 Router、Graph、Field 的内部实现。

DEVELOPER ACCESS · PLANNED

稳定、版本化、可替换客户端

API 文档计划包含接口定义、认证方式、请求与响应格式、错误处理和示例代码；SDK 与参考客户端可以在其上独立升级，而不用依赖 Core 的内部代码结构。

  • 应用与自动化系统集成；
  • 自定义客户端和内部工具；
  • 批量或流程化研究请求；
  • 基于公开契约构建第三方适配器。

Open access, private core

前端开放，后端闭源

TopicLens-Access 与 TopicLens Core 严格分离。公开客户端可以不断增加和替换，但不会因为 Access 开源而暴露私有后端、领域知识资产和内部运行机制。

Access 可以公开

用于说明和实现“怎样使用 TopicLens”。

  • Web / 小程序访问端
  • Agent Skill、MCP Server 或适配器
  • API / SDK 客户端
  • 配置模板与示例程序
  • 部署脚本、用户与集成文档
  • 公开接口 Schema 与兼容性说明

Core 保持私有

用于真正执行研究并长期积累知识。

  • TopicLens Core 后端源码
  • Router 核心研究决策逻辑
  • Graph 研究执行与编排实现
  • Field 私有数据、Catalog 与 Evidence Store
  • 内部 Prompt、Provider 配置与商业策略
  • 生产环境凭据与内部基础设施配置
